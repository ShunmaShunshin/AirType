# AirType 传输协议 v2

> 与老版 Phmic 的 **v2 协议完全互通**：AirTypePC 可作为老版 PhmicPhone 的电脑端，AirTypePhone 也可连接老版 PhmicPC。
> v2 核心安全点：**配对码不以明文出现在任何网络报文中**。手机先发起连接，电脑下发随机挑战，手机回传 `SHA-256(code ‖ nonce)`，校验后放行。

## 1. 总则

- 传输层：TCP（数据）+ UDP（发现）。
- 默认端口：TCP **47555**，UDP **47556**（可配置，两端需一致）。
- 编码：UTF-8。
- 帧格式：**换行分隔 JSON**（单行 JSON 对象 + `\n`；字符串内换行由 JSON 转义）。
- 版本字段 `v`：beacon 为 2；TCP 帧不带 `v`，但握手必须按 v2 流程，未知帧回 `bye` 并断开。

## 2. UDP 发现（beacon）—— 不含配对码

电脑每 **1000ms** 向各活动网卡子网广播地址与 `255.255.255.255` 发送一帧：

```json
{"t":"beacon","v":2,"n":"我的电脑","p":47555,"i":"a1b2c3d4","ver":"1.0.0"}
```

| 键 | 含义 |
|---|---|
| t | `beacon` |
| v | 协议版本，2 |
| n | 电脑显示名 |
| p | TCP 服务端口 |
| i | 实例 ID（每次启动随机 8 位十六进制），手机据此丢弃已重启/失联电脑的旧条目 |
| ver | 应用版本号（展示用） |

**安全**：广播不含配对码；手机须由用户输入屏幕上显示的码。

## 3. TCP 配对：挑战-应答认证

1. 手机向电脑 TCP 端口发起连接。
2. 手机先发设备名：`{"t":"pair","d":"Pixel 8"}`
3. 电脑生成 16 字节随机数 nonce，应答：`{"t":"challenge","n":"3f9a...（32 位十六进制）"}`
4. 手机在 15 秒内回传认证帧：`{"t":"auth","d":"Pixel 8","h":"5f4dcc...（64 位十六进制）"}`
   其中 `h = lowercase(hex(SHA-256(UTF8(code + nonce))))`。
5. 电脑校验：
   - 成功：`{"t":"pair","ok":true,"n":"我的电脑"}`
   - 失败：`{"t":"pair","ok":false,"e":"bad-code"}` 后关闭连接。
6. 约束：challenge 一次性有效（15 秒 / 已应答即作废）；未认证连接 20 秒无活动断开；未认证不能发 `text`。

## 4. 业务帧

### 4.1 发送文本（手机 → 电脑，需已认证）

```json
{"t":"text","id":3,"s":"要上屏的文本"}
```

电脑执行上屏后必须回：

```json
{"t":"ack","id":3,"ok":true}
```

失败时 `{"t":"ack","id":3,"ok":false,"e":"原因"}`。

### 4.2 心跳

空闲时每 15s 手机发 `{"t":"ping"}`，电脑回 `{"t":"pong"}`；任一方读超时 45s 关闭连接。

### 4.3 服务端关闭

`{"t":"bye","e":"shutdown"}` 后关闭。

## 5. 错误与重连

- 手机断线自动按最近成功参数每 3s 重连（需重走挑战-应答，本地已存码则静默完成）。
- 码错误：电脑回 `pair ok:false` 并断开，手机提示"配对码错误"并停止自动重连。
- 半包/粘包按 `\n` 切帧；连续 5 帧坏数据断开。
- 识别到 beacon `i` 变化（电脑重启）时手机可移除旧条目。

## 6. 扩展约定

- `x-` 前缀自定义帧两端容忍并忽略；语义变更时递增 `v`。
